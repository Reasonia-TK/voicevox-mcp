# 設計

## 目的

CodexとClaudeの最終回答、作業完了、エラー、確認待ちを、VOICEVOXの短い音声で補助的に伝える。画面表示を主とし、音声障害でAIアシスタント本来の処理を止めない。

## 対象としないこと

- AIクライアントのフックによる強制実行
- VOICEVOX本体や音声モデルの配布・自動ダウンロード
- VOICEVOXデスクトップGUIの自動操作
- リモートTTSサービス、認証、課金
- Windows以外での音声再生

## 構成

| コンポーネント | 責務 |
|---|---|
| MCPサーバー | ツール登録、利用条件の`instructions`、入力検証 |
| Engine Manager | ヘルスチェック、実行ファイル検出、多重起動防止、自動起動 |
| VOICEVOX Client | `/version`、`/speakers`、`/audio_query`、`/synthesis` |
| Speaker Resolver | キャラクター名・スタイル名・IDの解決 |
| Playback Queue | 本文を含まないジョブ、プロセス間連番、FIFO |
| Playback Worker | 排他再生、停止要求、一時ファイル削除 |
| PowerShell Player | `.NET System.Media.SoundPlayer`による同期WAV再生 |

## 読み上げ処理

1. MCPの`speak`が本文、音声、話速を検証する。
2. `/version`が正常なら既存Engineを使用する。
3. 接続不能なら、プロセス間ロックを取得して再確認する。
4. `VOICEVOX_ENGINE_PATH`または標準インストール先から`run.exe`を探す。
5. 見つかった場合だけ、`--host`と`--port`を指定して非表示・デタッチ状態で起動する。
6. `/speakers`からキャラクターとスタイルを動的に解決する。
7. `/audio_query`でクエリを作り、話速を反映して`/synthesis`でWAVを得る。
8. WAVと本文を含まないジョブJSONを共有FIFOへ原子的に追加する。
9. デタッチした再生ワーカーが排他ロックを取り、1本ずつ再生する。
10. 再生後にWAVとジョブを削除する。Engineは終了しない。

## 自動起動の分岐

| 状態 | 動作 |
|---|---|
| `/version`がVOICEVOX形式で応答 | そのまま使用 |
| 接続不能、自動起動有効、実行ファイルあり | バックグラウンド起動して待機 |
| 接続不能、自動起動無効 | `ENGINE_NOT_RUNNING` |
| 接続不能、実行ファイルなし | `ENGINE_NOT_FOUND`と設定方法 |
| 指定先が応答するがVOICEVOX形式でない | `ENGINE_ENDPOINT_INVALID`。相手を終了しない |
| Windows・ループバックHTTP以外で自動起動 | `PLATFORM_UNSUPPORTED` |

実際の起動処理ではEngineのディレクトリをカレントディレクトリにし、標準出力・標準エラーをユーザーデータ配下のログへ接続する。MCPの標準出力にはログを出さない。

## 排他制御とFIFO

排他制御はネイティブ依存を避けるため、ディレクトリの原子的な作成をロックとして使う。所有PIDが生存しているロックは保持し、所有PIDが終了したロック、または所有情報を書けないまま一定時間経過したロックだけを回収する。

キュー追加時は共有ロック内で単調増加する連番を確定する。同じミリ秒に複数クライアントが追加しても、再生順は連番で一意になる。ジョブJSONには次の情報だけを保存する。

```json
{
  "id": "UUID",
  "sequence": 1,
  "createdAt": "ISO 8601",
  "character": "ずんだもん",
  "style": "ノーマル",
  "speakerId": 3
}
```

読み上げ本文は保存しない。停止要求は制御ファイルでワーカーへ伝え、ワーカーが保持するPowerShell子プロセスだけを終了する。

## MCPツール境界

- `speak`: Engine自動起動、合成、キュー追加を行う。
- `voicevox_status`: 読み取り専用。Engineやデータディレクトリを作らない。
- `list_voices`: 読み取り専用。停止中のEngineを自動起動しない。
- `stop_speaking`: 現在の再生と待機ジョブを取り消す。

通常の途中経過を読み上げない判断は、MCPサーバーだけでは決められない。MCPの`instructions`と、各クライアントのグローバル指示を併用する。これはモデルへの指示であり、フックのような決定的保証ではない。

## セキュリティとプライバシー

- 既定接続先は`127.0.0.1`。
- 自動起動はWindowsのループバックHTTPだけ。
- 実行ファイルの自動取得や任意プロセスの終了はしない。
- MCPの標準出力はJSON-RPC専用。
- 本文はログとジョブへ保存しない。
- 一時WAVは再生後に削除する。
- 設定値に秘密情報を必要としない。

## 検証方針

- 単体: 設定、話者解決、API形式、多重起動分岐、実行ファイル不在、FIFO連番、停止時のキュー削除。
- プロトコル: STDIOで`initialize`、server instructions、`tools/list`を確認。
- 実機・無音: 起動済みEngineのバージョン、ずんだもんID、WAV合成を確認。
- 実機・音声: 非同期再生、WAV削除、再生中停止を短いスモークテストで確認。
- 配布: npm tarballの実インストール、MCPBスキーマ検証とアーカイブ作成。

利用中のVOICEVOXを強制終了する自動起動実機テストは行わない。自動起動分岐はモックで検証し、必要なら専用の検証端末または代替ポートで追加確認する。
