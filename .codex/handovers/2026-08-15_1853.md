## Decisions

- 配布とWindows互換性を優先し、実装言語はNode.js / TypeScriptとした。
- hookは使わない。音声実行は明示的なMCP tool callと、AIクライアント向けグローバル指示で制御する。
- Engineは起動済みなら指定loopback portへ接続し、停止中ならインストール済み実行ファイルだけを非表示で起動する。
- EngineやVOICEVOX本体の自動ダウンロード、GUIの自動起動はしない。
- 起動したEngineは読み上げ後も停止しない。
- 音声と画面表示は同じ結論・ニュアンスにする。
- 通常の途中経過は読み上げず、重要な節目だけを音声化する。
- npmの今後の公開は、手入力OTPや長期tokenではなくGitHub Actions OIDCを正式経路とする。
- Computer Use用notifyは別機能なので残し、音声hook部分だけを取り除いた。

## Pitfalls and Warnings

- `@t09tanaka/mcp-simple-voicevox`、旧PowerShell音声通知、hookベースの読み上げを復元しない。
- `notify` 全体を削除しない。Computer Useのturn-ended通知を担っており、削除対象は旧音声通知への連鎖だけだった。
- hooksをグローバルに無効化するための `[features] hooks=false` は設定しない。他機能やpluginのhookまで止める可能性がある。
- Claude接続確認がsandbox内で `CONNECTION_CLOSED` になった際、MCPの非互換ではなくnpm cache配下への書込み `EPERM` が原因だった。stderrを確認し、通常のWindows権限で再実行するとConnectedになった。
- Claude CLIの `mcp add` はserver名より前に `-e` を並べると、`Invalid environment variable format: voicevox` になった。READMEの確定コマンドかJSON例を使う。
- Codex CLIの検証時、このPowerShellでは `CODEX_HOME=C:\Users\TK\.codex` を明示しないと `No MCP servers configured yet` になった。実ファイルは `C:\Users\TK\.codex\config.toml`。
- `build\publish-with-otp.ps1` は文字化けによりPowerShell parser errorになった。今後の公開経路には使わない。
- npm Trusted Publisherの登録成功は確認済みだが、OIDC publish自体の成功とは別。`v0.1.1` のActions結果を必ず確認する。
- 旧試作ディレクトリとhookファイルは完全削除で、リサイクルビンからは復元できない。必要ならGitHub/npxの正式版を使う。
- 読み上げ失敗で本来の回答を止めない。画面回答を返し、音声連携エラーと設定確認方法を短く示す。

## Discarded Options

- hookでUserPromptSubmit、Stop、作業開始、通常の途中経過を機械的に読み上げる方式: 重複通知と過剰読み上げを生むため廃止。
- 旧 `@t09tanaka/mcp-simple-voicevox` の併存: 正式版と機能が重複し、設定先も分散するため削除。
- PowerShellからVOICEVOX APIを直接叩くone-liner: クライアント横断のキュー、起動管理、停止、設定診断を統一できないため不採用。
- npm OTP入力用の公開スクリプト: 文字コード事故があり、継続運用にも向かないため廃止。
- npm granular access tokenを恒常的な公開経路にする案: 秘密管理と2FA bypassのリスクがあるため、OIDCへ移行。
- `claude mcp add-json` による登録: この環境では `Invalid configuration: : Invalid input` となったため、確定済みの `claude mcp add --transport stdio --scope user ...` を採用。
- hooksを機能フラグで全面停止: voice以外を巻き込むため不採用。
